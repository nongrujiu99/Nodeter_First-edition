# 生产上线基线

应用代码可以提供稳定能力，但正式上线还依赖部署环境、监控平台和运维主体。宝塔、Docker、云容器和托管 PostgreSQL 使用同一检查标准。

## 当前验收证据边界

- 当前本地发布门禁已通过：Web `470` 个测试文件通过、`4` 个按环境跳过，`2087` 项测试通过、`9` 项跳过；依赖审计为 0 个已知漏洞，ESLint、Prettier、TypeScript、63 页生产构建和 Standalone 资源检查均通过。Docs 的依赖审计、类型、索引和 36 页生产构建已通过。Playwright 在同一生产构建上完成桌面、390px、430px 共 `98` 项，另有 `14` 项按数据库环境或项目互斥范围跳过，覆盖安装、首页、Canvas、文本/图片/视频/音频、统一 Agent、删除持久化和响应式布局。本轮另外使用现有管理员登录态手动复核用户运营、基础设置、模型渠道、外部存储和数据备份的保存往返及 390px/430px 浅深主题；这些人工检查不计入 Playwright 数量。当前环境未配置隔离 `VOZEB_PRO_E2E_DATABASE_URL`，真实 PostgreSQL 多实例并发仍需在专用数据库执行。
- 生产页面 CSP 使用每请求随机 nonce，主题预加载脚本、Next.js 运行脚本与响应头使用同一 nonce；连续请求 nonce 不同，生产 `script-src` 不含 `unsafe-inline`，完整浏览器矩阵未出现 CSP 控制台错误。对象存储配置、渠道密钥查看和业务备份导出/恢复的成功/失败路径已写入管理员审计日志，且不记录密码、动态码、密钥、证书或备份正文。管理员 TOTP MFA、登录环境变化提醒、本人分页登录记录和显式职责权限体系已完成代码；后台业务逐次密码/MFA 复核已取消。真实管理员设备启用、生产登录、设备丢失恢复、多职责越权拒绝、异常登录处置和审计演练仍是独立的上线治理阻断项。
- 开源发布安全基线已增加系统渠道代理允许列表与逻辑模型授权、公开 Session 白名单、IP/账号/设备三维认证限流、密码重置统一响应和 GitHub Skill commit/内容哈希固定，以及正式 Tag 镜像门禁、SPDX SBOM、Cosign digest 签名和 attestation。Agent Run 现在保存当次实际 Skill 的完整不可变执行快照，公开 Run 与 SSE 白名单不会返回这些内部规则。CodeQL 报告的 10 条告警已通过受控请求传输、结构化 URL/HTML 解析、无偏加密随机数和单次实体解码完成代码修复，未使用规则忽略；仍需由 `v0.0.6` 后续推送后的远端扫描确认告警关闭，本次本地提交不会上传 GitHub。许可证只作为来源元数据，不是导入门禁。代码与契约测试通过不代表真实反向代理、文本模型质量、GitHub OIDC 或多实例 PostgreSQL 已完成生产验收。
- 当前 PostgreSQL 审计实例的昱梦渠道已配置图片和视频逻辑模型，Base URL 已修正为 `https://zcbservice.aizfw.cn/kyyReactApiServer`，创建与查询使用完整 `/kyyReactApiServer/v2/model-center/tasks` 与 `/kyyReactApiServer/v2/model-center/tasks/:task_id` 路径，API Key 密文和 29 个预置模型未改动；内部代理会对旧 `token.myairealm.com` 门户地址做确定性修正，并避免重复拼接 `kyyReactApiServer`。New API 渠道继续提供文本、图片和音频默认模型。本地自建 TCP 接口已由完整协议注册表和 GlobalAiOpc 预置表逐项驱动，覆盖文生/参考图、异步查询、模型白名单、协议鉴权和实际媒体读取。夹具与代理测试只证明应用侧协议实现，不能替代真实供应商生成、媒体质量或 SLA 证据。
- PostgreSQL 实际 59 张 `vozeb_pro_*` 表均能对应 Schema、Repository、外键、业务读取或旧表清理职责，不能按当前行数为零直接删除。两条历史图片任务因上游提交结果不确定、没有任务 ID 与查询路径进入 `needs_review`；这是避免重复生成的安全暂停，仍需管理员结合供应商日志人工确认。
- PostgreSQL 的 Canvas、素材库、用户媒体和生成日志在线路径已收敛为用户范围分页或按后台配置的稳定批次；完整认证、提示词和生成记录快照只接受管理员备份事务。管理员永久删除用户时会在用户行锁事务内先分页快照媒体登记，再让数据库级联业务记录，提交后重新统计引用并清理本地/S3 对象。该自动化只证明代码编排和引用保护，尚未覆盖生产对象删除失败、跨业务共享引用；上线前必须用隔离 PostgreSQL、本地媒体与真实 S3 完成可恢复演练并保存证据。
- 反向代理转发域名和 HTTPS 只在 `VOZEB_PRO_TRUSTED_PROXY_HOPS` 大于零时接受。生产验收必须确认该值与真实代理层数一致，避免信任用户伪造的转发头。
- 七套 Compose 与 Render Blueprint 已通过结构化契约测试。五套主应用 Compose 锁定 app/Worker 同镜像、独立维护/Worker 令牌、Worker 命令、数据库最小权限、存活探针、持久卷、内置/外部 PostgreSQL 分界和宝塔 host 网络隔离；Worker 不再取得外部维护令牌。两套文档 Compose 锁定独立端口和发布/本地构建来源。Render 进一步锁定付费 Web/Worker、共享 Worker 令牌、Web 独立维护令牌、私网调用、`basic-256mb` PostgreSQL、10GB 持久盘和生产镜像脚本。v0.0.3 发布镜像已在一台 Linux x64 服务器暴露 Sharp 的 `libvips-cpp.so.8.18.3` 缺失，导致生成运维接口与 Worker 返回 500；生产 Dockerfile 现已显式复制当前架构原生包并在镜像构建阶段加载 Sharp。本机没有 Docker CLI，也没有 Render 账号部署证据，新镜像仍需完成 `docker compose config`、拉取与启动、两个生成运维接口、Worker 心跳、图片 WebP 预览、Blueprint 创建、宝塔安装和干净 Linux 恢复验证。
- 浏览器前序回归已覆盖主要桌面、390px/430px 和浅深主题页面；新构建切换后又使用现有管理员登录态复核后台、Agent、图片、视频、Canvas、短剧和素材页面，桌面与 390px 加载为 210–396ms，根节点无横向溢出且控制台无 warning/error。生产发布仍需按目标浏览器、真实账号、真实媒体和生产网络完成最终人工验收。
- Canvas 独立重写已通过依赖清单、Canvas 源码标识和旧入口边界测试，当前画布不引入目标仓库或第三方画布包；这只是代码来源审计证据，不替代对第三方依赖许可证的合规审核。正式发布前仍需保留实现来源记录，并复核 clean-room 过程与全部供应商许可证。

## 健康检查

- `GET /api/health/live`：只检查 Web 进程是否能响应，Docker Compose 使用该地址，避免数据库短暂异常导致应用容器反复重启。
- `GET /api/health/ready`：检查数据库连接、表结构、加密密钥和首个管理员；未完成安装或依赖异常时返回 HTTP `503`，用于反向代理、负载均衡和外部监控。
- `/api/install/status`：面向安装页面的安全状态，不应作为生产告警依据。

## 计划任务

配置至少 32 个字符的 `VOZEB_PRO_MAINTENANCE_TOKEN`，定期调用维护接口：

```bash
curl -fsS -X POST \
  -H "Authorization: Bearer $VOZEB_PRO_MAINTENANCE_TOKEN" \
  https://vozeb-pro.example.com/api/maintenance/...
```

宝塔使用计划任务，Docker 使用宿主机 Cron，云平台使用 Scheduler。多实例通过数据库锁避免重复执行。

## 备份与恢复

- 后台”数据备份”导出与恢复要求当前管理员 Session 具备 `system.manage`，不再逐次要求当前密码或 TOTP；导出通过无请求体的独立 POST 返回 `private, no-store` 脱敏业务数据，恢复 multipart 只提交备份文件。该数据只用于 `account-config` 合并恢复账号、非敏感设置、公共提示词和生成记录；导入不会删除备份中缺失的用户或记录，PostgreSQL 使用事务与锁，文件 Provider 失败时回滚原快照。业务 JSON 不包含 Canvas、素材、媒体原件、短剧和对象存储完整清单，不能作为整库灾难恢复包。
- 管理员 MFA Secret 不进入常规业务备份；恢复业务包不能替换、启用或关闭服务器现有 MFA。管理员丢失身份验证器时可在服务器执行 `pnpm -C web reset:admin-mfa -- --username <账号>`，命令会清除目标管理员 MFA 并撤销其全部 Session；文件 Provider 修改前保存恢复副本，PostgreSQL 使用事务。该命令是账号访问恢复能力，不替代完整灾难恢复演练。
- PostgreSQL 使用数据库平台或 `pg_dump` 做整库备份；密钥不依赖业务 JSON 备份。
- 本地媒体目录、S3/OSS 对象和对象存储配置分别备份；不要只备份数据库后假设媒体能够恢复。
- 至少保留每日自动备份、异地副本和定期恢复演练。备份任务成功不等于恢复可用。

## 监控与告警

根据部署环境选择 Sentry、OpenTelemetry、云厂商 APM、Prometheus/Grafana 或日志平台，不要求所有部署同时安装同一套组件。上线前至少覆盖：

- `/api/health/ready` 可用率和连续失败。
- Web CPU、内存、磁盘、容器重启和媒体容量。
- PostgreSQL 当前连接数、连接池等待、慢查询、锁等待和存储增长。
- API P50/P95/P99、HTTP 5xx、登录失败率和限流触发量。
- 图片、视频、音频和 Agent 的成功率、耗时和渠道冷却次数。

服务器日志可能包含内部错误细节，应限制管理员访问并设置保留周期；密钥、登录令牌和媒体签名参数不得写入日志平台。

私有媒体已按用户归属或绑定资源/用途/过期时间的短期签名读取，本地与代理 Range、HEAD、条件缓存、分层限流和进程内并发回收已有自动化证据。真实代理跳数、多实例限流、私有 S3、热点资源、文件句柄与外网下行仍必须在生产等价环境压测，代码上限不能替代容量证据。

## 容量与压测

先以生产相同数据库、代理和存储进行 100、500、1000 并发分级测试，记录登录、列表、生成任务创建、SSE 连接和后台查询的 P95/P99。根据瓶颈再调整 `VOZEB_PRO_DATABASE_POOL_MAX`、实例数、队列或缓存，不要仅靠增大连接池解决并发问题。

短剧项目概览已改为按用户、项目、任务类型和状态在 PostgreSQL 聚合，并增加项目定向索引；本地执行计划命中 `generation_tasks_user_project_idx`，Canvas、素材和会话分页也具备定向索引路径。该证据只覆盖当前小数据集，仍需在生产等价任务规模下记录 P50/P95/P99、连接池/锁等待结果。

## 异步生成任务

图片、视频、音频和 Agent 任务需要在真实渠道下验证排队、超时、取消、重试、断线恢复、重复提交和卡死任务接管。重启和多实例竞争不能造成重复资产或任务状态不一致。

当前代码已提供页面定向唤醒、独立生成 Worker、PostgreSQL 租约、心跳就绪检查、HMAC 回调幂等登记和 `needs_review` 管理员接管。普通 Agent 生成完成后可由持久 Worker 继续内部复盘，进程重启后仍可恢复，复盘最终不可用不会撤销成功媒体；`needs_revision` 只保存内部建议，不会自动重新创建上游媒体任务。用户端 SSE 断线时不按固定失败次数终止，而是继续等待 EventSource 自动重连并复用单个服务端 Run 状态核对；切换对话也只停止当前页面观察，不改变后台 Run。Planner 只按 Surface 与能力筛选已验证模型和用户显式 Skill，完整发送会话上下文、参考资产与项目快照，不再由平台叠加固定字符、输出 token 或节点数量上限；真实供应商上下文窗口和拒绝行为仍需单独验收。PostgreSQL Run 事件使用事务内 `NOTIFY` 和独立 `LISTEN` 连接即时唤醒 SSE，现有轮询只承担通知丢失兜底。本地协议矩阵已按注册能力核对任务完成、媒体解析/落盘、资产登记、查询路径、模型目录和鉴权头，并覆盖 Worker 查询和人工确认失败。这些结果不能替代默认 Docker、宝塔、低内存、外部数据库、多实例和真实供应商下的无人页面运行、通知丢失、接管竞争和媒体登记证据。

混合模型渠道可以按模型保存 OpenAI、Gemini、Seedance 2.0 或兼容协议与创建/查询路径，但代码适配不能替代供应商文档和真实密钥验收。上线前应逐渠道保存实际模型目录响应、分页证据及文本/图片/视频最小调用结果；上游未公开目录或使用不透明模型名时，必须由管理员维护模型能力与路由，不能把名称猜测当成生产证据。

系统渠道的调用身份由服务端绑定用户、业务请求、逻辑模型、渠道和上游模型生成，普通用户提交的幂等头不会直接成为调用键；请求指纹会拒绝同身份不同参数的重放。重试、上游暂停和降级规则必须来自供应商公开约束、管理员配置或已有且可验证的资源保护契约，不能新增拍脑袋的固定次数、延时或输出上限。

## 安全事件与数据泄露响应

正式上线前需要单独准备并演练安全事件响应手册，不能把它拆散在”密钥加密”和”日志监控”两项里：

- 针对模型密钥、维护令牌、OSS 凭据、Session 和个人数据泄露，明确发现、分级、隔离、吊销、轮换、取证、修复和复盘责任人。
- 覆盖异常登录、越权访问、私有媒体暴露和数据库泄露，保留必要证据，并按合同要求判断是否需要通知用户或供应商。
- 演练暂停受影响模型渠道、撤销会话、轮换密钥、恢复备份和重新验证媒体引用；不能因为处置事件而静默损坏生成记录。
- 依赖扫描、加密存储和已有健康探针只能作为技术基础，不能替代可执行的事件响应、通知和恢复证据。

## 供应商与安全治理

- 为模型渠道、SMTP 和对象存储建立供应商清单，记录配额、数据区域、保留期限、SLA、停服通知和替代渠道。
- 落实 Business Source License 1.1、第三方依赖、字体和素材许可证义务，保留许可证与版权声明；正式发布前完成依赖、容器镜像和密钥泄露扫描，并建立漏洞披露、修复和安全公告流程。
- 明确模型渠道故障、配额耗尽和模型下线时的降级与暂停规则。

## 技术运维缺口

下面事项不能由应用代码或宝塔面板自动完成，正式上线前必须由技术负责人确认：

- **权限与审计**：后台已在管理员角色内提供多项显式职责与预设，覆盖上游运维、系统运维和只读审计；管理员不能授予超出自身范围的职责，也不能修改或删除职责范围高于自己的管理员。正式团队运营前仍应为每个账号分配最小职责，并定期权限复核。
- **事故与服务**：明确版本发布、回滚、值班、故障分级和状态通知规则。健康探针、日志和告警是技术基础，不等于已经建立 SLA 或人工响应流程。

## 容易遗漏的上线控制项

以下事项经常不在”功能已完成”清单中，但会直接影响上线后的安全和运维责任：

- **管理员高风险保护**：TOTP MFA、登录环境变化提醒、本人登录记录、显式职责权限和后台成功/失败审计已提供技术能力；设置、密钥、存储和备份按用户要求取消逐次密码/MFA 复核。上线前仍须为生产管理员真实验证登录 MFA、身份验证器丢失恢复、Session 撤销、越权拒绝、异常登录处置和审计记录，并由负责人确定短会话、双人审批、紧急访问和定期权限复核规则。
- **密钥生命周期**：建立加密密钥、模型密钥、维护令牌和 OSS 凭据的创建、保管、轮换、吊销和泄露应急流程；恢复备份时必须同时验证密钥可用性，不能只恢复数据库和媒体。
- **数据生命周期**：后台已提供显式维护入口，按管理员开关和批次清理具有明确技术到期时间的 Session、邮箱验证码、生成任务和无引用临时媒体；普通在线读写不再顺手执行无界清理，PostgreSQL 与文件 Provider 都使用稳定排序和有界批次。上线前仍须为对话、长期媒体、WebP 变体和审计记录确定保留期限、用户删除触发、合规保留例外、调度负责人和删除结果核验，代码不会猜测这些制度。
- **存储与网络成本**：按本地磁盘、OSS 请求、存储容量、外网下行、CDN/代理和备份副本建立成本监控，设置容量、带宽和对象存储账单预警；S3 开关本身不等于成本治理。
- **故障沟通**：准备状态页或通知替代方案、维护通知模板和生成失败/上游停服的用户文案，明确谁有权暂停某个模型渠道。
- **无障碍与浏览器支持**：在目标浏览器和移动端完成键盘操作、焦点顺序、表单错误、对比度、动态状态播报、媒体替代文本和下载行为验收，并公布最低支持范围。
- **通知可达性**：验证验证码、密码重置和故障通知的实际送达；配置发信域名 SPF/DKIM/DMARC，监控退信与投诉，保留模板版本，并为通知供应商故障准备人工或站内通知兜底。
- **环境与回滚**：开发、预发布和生产必须隔离数据库、对象存储桶、模型密钥、维护令牌和回调域名；每次发布都要有迁移前备份、冒烟检查、可替换镜像和回滚后数据兼容记录。
- **上线证据**：每项 P0/P1 控制项都应登记负责人、截止时间、环境、证据链接、复核人和复核日期；没有真实通知、恢复、压测或安全演练证据时，仍标记为未完成。

这些控制项应落到负责人、截止时间、证据链接和复核结果；没有证据时继续标记为未完成，不要因为已有接口、后台开关或自动化测试就视为闭环。

### 上线判定

1. 任一阻断项没有负责人、复核人和真实证据时，只能进入内部或封闭测试，不能宣称正式上线。
2. 代码测试、健康探针、后台开关和配置页面只能证明技术基础，不能替代 OSS、邮件、代理、恢复和人工流程验收。
3. 灰度期间每周复核生成成功率、存储增长和供应商异常；发现安全风险时立即暂停对应渠道并保留用户数据。
